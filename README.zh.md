# Y-API 价格表 —— 重算出来的，不是抄来的

[English](README.md) · **简体中文** · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Deutsch](README.de.md) · [Português](README.pt.md)

> **利益声明：** 我在做 Y-API，所以这是第一方工具读第一方文件。它打印的一切都来自 <https://y-api.bestvirtualgoods.com/pricing.json>——该文件公开、无需 key。你可以自己跑一遍脚本，拿输出去对源文件。

一个脚本，零依赖，不需要 API key。它读取 Y-API 发布的价格文件，渲染出带**现金价**的 [table.md](table.md)——现金价才是真正从你卡里出去的数字，也是唯一能拿去和别家标价对比的数字。

## 为什么要做这个

Y-API 的标价单位是**额度**，当前充 1 美元得 20 美元额度。额度是账户余额被扣的数，不是你卡里被扣的数。只标额度的表会让每个模型看起来贵 20 倍；而硬编码"除以 20"的表，在促销汇率结束那天会静默变成错的。这个脚本从**同一个文件**里读出汇率，再读出价格。

## 怎么跑

```bash
node price-table.mjs > table.md                            # 拉线上文件
PRICE_JSON=./pricing.json node price-table.mjs             # 渲染本地副本，离线可跑
```

需要 Node 18+（用到全局 `fetch`）。本仓库的 `table.md` 由 GitHub Action 每周一重新生成，**只在有变化时才提交**——所以提交历史本身就是价格变动日志。

## 脚本守的两条规矩

违反任何一条，产出的表都会和它来源的那个站点悄悄对不上。

1. **现金价是重算的，不是抄的。** 文件里已经发布了 `cash_price`，但脚本仍会重算 `credit_price / top_up.quota_rate`，**两者不一致就直接报错退出**。过期的汇率、手改过的数字，都混不进这张表。
2. **`vendor_cheaper_on_cached_input` 绝不单独打印。** 这个标记的意思是：厂商的缓存命中价低于我们的现金价——对重缓存的负载来说我们更贵。但有些行同时带着 `historical-price`（厂商价来自过期的价目表），Y-API 站点会有意把这些从"我们在缓存上输"的计数里排除掉。**只印标记不印 caveat，读者就会拿走一个错误的计数。** 所以两列一起给。

## 怎么看输出

- **模型目录**——全部模型，额度价与现金价，每百万 token，按价格排序。
- **对上厂商自己的标价**——11 个模型带我们核实并标注出处的厂商官方价，含倍数、缓存标记、caveats、核实日期与厂商页面链接。剩下 4 个明确标为"没有可核实并引用的厂商价"；文件是照实写，不做估算。

`× 我们` 读作"厂商收的是我们现金价的多少倍"——倍数大是**我们更便宜**，不是更贵。

## 边界，照实说

- 这张表的新旧程度不会超过源文件。表头里印着源文件的 `synced_at` 和渲染日期；两个都旧了，那这里就没有新信息。
- 它只渲染**一个**网关的价格。不做跨厂商对比，也不记录别家的价格史。
- 价格会变，而充值汇率是限时的、结束日期未公布。要拿这张表做决定，请回到源文件重算，别抄 `table.md` 的副本。
